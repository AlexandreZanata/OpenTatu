# Part B — Memory and history of each application

## B.1 Principle: three memory layers

1. **Event log (source of truth)** — the `events` table in SQLite, append-only. Everything
   that happens becomes an event with date, time, actor and target. It is mirrored to
   `history.jsonl` at the end of each audit, for backup and portability.
2. **Derived state** — current findings, current map, open tasks. It can be rebuilt from the
   events at any time.
3. **Working memory (`MEMORY.md`)** — a short readable summary (at most ~2,000 tokens) that
   the investigator receives at the start of each audit. Generated by the system from the
   derived state; never edited by hand by the AI.

Artifacts (reports, evidence, raw scanner outputs) live in the filesystem, referenced by
events.

## B.2 Identifiers

| Item | Format | Example |
|---|---|---|
| App | lowercase slug | `abastevo` |
| Audit | `AUD-<SLUG>-<YYYYMMDD>-<HHMM>` (same-minute collision: suffix `-2`, `-3`...) | `AUD-ABASTEVO-20261129-1432` |
| Finding | `<SLUG>-SEC-<NNNN>`, sequential per app, never reused | `ABASTEVO-SEC-0004` |
| Hypothesis | `<AUDIT>-H-<NNN>` | `AUD-ABASTEVO-20261129-1432-H-001` |
| Evidence | `<AUDIT>-EV-<NNN>` | `AUD-ABASTEVO-20261129-1432-EV-001` |
| Task | `<FINDING>-T<N>` | `ABASTEVO-SEC-0004-T1` |
| Event | `EVT-<NNNNNNNN>`, global sequence | `EVT-00000184` |
| Map version | `MAP-<SLUG>-<YYYYMMDD>-<HHMM>` | `MAP-ABASTEVO-20261129-1432` |

Implemented in `opentatu_core::ids` (see Q-001 about which timestamp stamps the audit ID).

## B.3 Dates and times

- Storage: ISO 8601 with offset, e.g. `2026-11-29T14:32:00-03:00`.
- Default time zone: `America/Sao_Paulo`.
- Owner-facing display (pt-BR): `29/11/2026 às 14:32 (horário de Brasília)`.
- Every audit stores: `created_at`, `started_at`, `completed_at`, `duration_seconds`.
- The AI model does not know what time it is. The orchestrator injects dates into prompts
  and records; the AI only repeats them when asked.

Implemented in `opentatu_core::time` (`Timestamp`, `Clock`).

## B.6 Events

Format of one event (`opentatu_core::Event`):

```json
{
  "event_id": "EVT-00000184",
  "kind": "FINDING_CONFIRMED",
  "app": "abastevo",
  "audit_id": "AUD-ABASTEVO-20261129-1432",
  "occurred_at": "2026-11-29T15:12:08-03:00",
  "actor": "verifier",
  "target": "ABASTEVO-SEC-0004",
  "data": { "severity": "HIGH", "fingerprint": "sha256:..." },
  "model": "<model id, if any>",
  "prompt_version": "verifier@1.0.0",
  "references_event_id": null
}
```

`actor` is `system`, `owner`, an AI role (`cartographer`, `hunter`, `verifier`, `skeptic`,
`planner`, `reporter`) or an external agent as `agent:<id>`. `references_event_id` is used
for record corrections (R04).

Event kinds (`opentatu_core::EventKind`):

- App: `APP_REGISTERED`, `APP_UPDATED`
- Audit run: `AUDIT_CREATED`, `AUDIT_STARTED`, `SNAPSHOT_CAPTURED`, `SCANNER_RAN`,
  `SCANNER_FAILED`, `MAP_UPDATED`
- Investigation: `HYPOTHESIS_CREATED`, `HYPOTHESIS_VERIFIED`, `FINDING_CONFIRMED`,
  `FINDING_UPHELD`, `FINDING_DOWNGRADED`, `FINDING_DISMISSED`, `FALSE_POSITIVE_RECORDED`
- Fix trail: `TASK_CREATED`, `TASK_CLAIMED`, `FIX_SUBMITTED`, `REVERIFICATION_PASSED`,
  `REVERIFICATION_FAILED`, `FINDING_CLOSED`, `REGRESSION_DETECTED`
- Risk: `RISK_ACCEPTED`, `RISK_EXPIRED`
- Safety and budget: `SUSPICIOUS_INSTRUCTION_DETECTED`, `BUDGET_EXHAUSTED`
- Audit end: `AUDIT_PAUSED`, `AUDIT_RESUMED`, `AUDIT_PARTIAL`, `AUDIT_COMPLETED`,
  `AUDIT_FAILED`
- Owner: `OWNER_DECISION`

## B.8 Fingerprint (identity of a finding across audits)

```text
fingerprint = sha256( cwe + "|" + file_path + "|" + symbol (function, route or class)
                      + "|" + normalized_relevant_snippet )
```

Normalization: remove extra whitespace, line breaks and comments. If a file was moved or
renamed, the hunter may suggest "possibly the same finding: <ID>"; the system compares and
decides.

Uses: deduplicate findings, prevent reopening false positives, detect regressions and count
"persistent" findings between audits. Implemented in `opentatu_core::fingerprint` (frozen by
a golden test).
